Leads Manager

Match the same person across general Slate leads, classroom lists, applicant reports, info-session registrations/attendance, and other person-level exports.

Person-level data: unlike the aggregate campaign dashboard, this manager stores names/contact identifiers in your local browser and JSON backups so records can be matched across files.
Info-session matching is automatic: Zoom registration and attendee files imported through the normal Import Center are also matched into this Leads Manager by email. You do not need to upload the same Zoom file twice.
Identity matching: exact normalized email is checked first. Legacy bare MSUNet IDs are matched only to the equivalent @msu.edu address. Global cleanup never merges people by first name, full name, or phone number.
Historical normalization: every time this version opens, it re-checks the complete saved history—not just the current month—including old lead/applicant dates, statuses, programs, email aliases, duplicate records, and evidence imported by earlier versions.
Info-session integrity: registration and attendance files for the same webinar are merged into one session. Participant emails are stored persistently and automatically re-applied to Leads Manager.
Event-aware search: the Leads Manager search now indexes linked event/session titles, event dates, event IDs, evidence types, and application history. Use the Linked event dropdown to isolate everyone connected to one specific event.
Info-session email reconciliation: historical and current session rosters are re-matched against all lead email aliases and applicant emails whenever data changes. Registration/attendance evidence is automatically restored to the person timeline.
Recruitment Activity linking: when importing a class/event roster, choose the exact activity under Link this roster to Recruitment Activity. The app matches those people to existing leads, adds the activity to each person’s history, and recalculates that activity’s Leads captured count.
Course-roster preservation: MSU course CSVs with Subject, Course, Section, Student Name, MSUNet ID, and Academic Plan are recognized separately. Section membership is stored as person-level evidence and can be mapped to different Recruitment Activities from one file.
Reliable lead imports: lead files now show an explicit importing state and visible errors. Exact-file duplicates no longer depend on a browser pop-up; they can be re-imported safely using the existing email/MSUNet identity rules.
Lead response management: select a person to record email replies, phone responses, event sign-ups, removal requests, program changes, or no-response outcomes. Removal requests flag the person Do Not Contact without deleting their history.
Info-session people are leads: every person on a registration or attendance roster is matched to an existing lead by email when possible. If no match exists, the app automatically creates a new lead with Information Session as the source. Existing leads keep their original source and gain the session interaction.
Session dedupe: one person can count only once as registered and once as attended for the same program + date + session title, regardless of which Zoom/master file or event ID created the row.
